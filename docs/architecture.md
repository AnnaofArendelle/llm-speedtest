# Architecture

llm-speedtest is a single Go module that ships one static binary. Every interface — CLI, HTTP API, web UI,
MCP server and the Agent skill — drives the same `app.Service`, so results are identical no matter how a run
was started.

```
cmd/llm-speedtest          flag-based sub-command dispatcher (internal/cli)
internal/app               Service: endpoints, runs, pipelines, event bus, exports
internal/server            net/http API (Go 1.22 pattern routing), SSE, static UI, optional bearer token
internal/mcpserver         Model Context Protocol server (stdio) built on the official Go SDK
internal/skill             embedded Agent Skills package + installer/exporter
internal/apiclient         OpenAI-compatible client: /models, chat (sync + SSE with per-chunk timing), embeddings
internal/dialect           structural gateway dialects (error unwrapping, health endpoints) — no name tables
internal/classify          nested error unwrapping and the 25-code failure taxonomy (zh/en texts)
internal/provider          data-driven provider resolution (discriminating power × consistency, overrides, suggestions)
internal/family            data-driven family grouping (tokeniser rules, alias learning, overrides)
internal/scan              multi-round availability engine (semaphores, lock-aware cooldown, backoff, resume)
internal/latency           streaming latency lab (TTFT, TTST, TPOT, ITL, E2E, tok/s)
internal/load              closed-loop / open-loop load generator, goodput under SLO
internal/capability        13 capability probes
internal/quality           deterministic question set and scoring
internal/metrics           quantiles (R-7), summaries, log-scale scores
internal/analyze           aggregation: model stats, families, providers, tiers, composite ranking
internal/report            Markdown / JSON / CSV exports (golden-tested)
internal/store             SQLite (modernc, WAL) with batched single-writer inserts and migrations
internal/secrets           AES-256-GCM key storage
internal/refdata           embedded anonymised reference scan (2 306 models) used by tests and demo mode
internal/demo              demo data seeding (`serve --demo`)
internal/testutil/mockllm  scriptable mock gateway used by every engine test
web/                       React + Vite + TypeScript dashboard, embedded via go:embed
skills/llm-speedtest       SKILL.md, scripts, references, assets
```

## Run pipeline

1. **Discover** – `GET /v1/models`, apply filters, resolve providers and families, store `run_models`.
2. **Scan** – rounds *first → retry → resample×N → final*; every attempt is written in batches and published on the
   event bus (SSE / CLI progress). Interrupted runs resume from stored attempts.
3. **Analyze** – model stats (tier, median, jitter, flaky reasons), family stats (composite score, stability rank),
   provider stats (rate, top reason, account-level flag) and summary buckets.
4. **Stages** (suite only) – latency lab, capability probes and quality check on the top-N models of the ranking, then an
   optional load test on the best model. Each stage is a child run with its own events and summary.
5. **Export** – the Markdown report reproduces the structure of the original audit; JSON carries `schema_version`.

## Concurrency model

- Global and per-provider semaphores limit in-flight requests; provider keys come from the dynamic resolver.
- Lock-aware cooldown: when a gateway reports `reset after …` / `retry-after`, the affected provider is paused up to
  `max_cooldown_wait`; transient errors use exponential backoff capped by `max_backoff`.
- Cancellation is cooperative: engines stop after the in-flight request and the run is marked `cancelled`,
  never `done`.
- The event bus keeps a bounded history per run with sequence numbers so SSE clients can resume with
  `Last-Event-ID`.

## Storage

Tables: `endpoints`, `provider_overrides`, `family_overrides`, `runs`, `run_models`, `attempts`,
`latency_samples`, `load_requests`, `cap_results`, `quality_results`, `schema_version`. The database lives in
`<data-dir>/llm-speedtest.db` (WAL mode); keys are encrypted with the master key in `<data-dir>/.secret`.

## Frontend

React 19, MUI 7, ECharts 6 (tree-shaken), framer-motion, TanStack Query, react-router 7, i18next. Design
tokens live in `web/src/app/theme.ts` (light/dark, A/B/C tier colours, latency chip scale). Pages are
code-split; the run dashboard tabs load lazily. Screenshots in `docs/screenshots` are generated by Playwright
against `serve --demo` (`make screenshots`).
